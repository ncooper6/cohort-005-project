# Pause a learner's access while their Refund Request is Open

A Refund is always the full amount paid. If a learner kept access to the course while their Refund Request waited for an Admin, they could finish the whole course in that gap and still get all their money back. So we pause a learner's access to the course as soon as they raise a Refund Request. If an Admin declines the request, or the learner withdraws it, access comes back. If an Admin approves it, access ends for good.

## Considered Options

- **Keep access, check the limits again when the Admin decides.** Rejected. It catches the loophole only after the learner has already used the course, and it turns every late decision into a dispute about which numbers count: the ones from when the learner asked, or the ones from now.
- **Keep access and leave it to the Admin.** Rejected. Closing the loophole would then depend on an Admin noticing the learner's progress on every request.
- **Pause access (chosen).** By asking for their money back, the learner has said they don't want the course, so pausing costs them little. A learner who is declined loses a few days of access, and we accept that cost.

## Consequences

- Whether a learner can watch a course now depends on their Refund Requests as well as on being enrolled. Anything that checks access has to respect the pause.
- How quickly Admins decide matters to learners, because a declined learner is locked out until the decision.
